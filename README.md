## Описание

Опросник без сохранения в базу данных и доступа к статистике и результатам. История опросов сохраняется только локально в браузере для каждого пользователя. При смене браузера, очистке кэша история будет стерта.

Доступны 5 языков: русский, английский, монгольский, казахский, узбекский. Список определяется файлами в папке `langs/`, см. раздел «Как добавить язык».

## Как подключить опросник

1.  Загрузить файлы из assets на хостинг/облако, чтобы были http ссылки на эти файлы

2.  Подключить файл стилей `style.min.css` и javascript-файл `app.min.js`. Через админку загрузить их для статьи, либо через облако загрузить оба файла и подключить по ссылке с облака.
    
3.  В html коде, к любому кликабельному элементу, надо добавить CSS класс `double-energy-poll-button`. Кнопка станет кликабельной и будет открывать опросник.
    
4.  Необязательные атрибуты кнопки:
    
    -   `data-logo="путь/к/nutrilite.svg"` — логотип в шапке опросника, взять ссылку на файл из облака, в которое загрузили файл на 1 шаге;
    -   `data-product="путь/к/double-energy-product.png"` — фото продукта на экране результата, взять ссылку на файл из облака, в которое загрузили файл на 1 шаге;
    -   `data-buy="https://…"` — ссылка на покупку, на сам продукт;
    -   `data-energy-logo="путь/к/double-energy.svg"` — логотип Double Energy на первом экране, взять ссылку на файл из облака, в которое загрузили файл на 1 шаге;
    -   `data-form-image="путь/к/form-ru.jpg"` — баннер на первом экране, взять ссылку на файл из облака, в которое загрузили файл на 1 шаге.
    
    Если `data-logo` не указан, шапка с логотипом не выводится. Если не указан `data-product`, на экране результата не выводится фото продукта (название остаётся). Если не указан `data-buy`, кнопки «Купить» нет, а фото и название не являются ссылкой. Если не указан `data-energy-logo`, на первом экране нет логотипа Double Energy. Если не указан `data-form-image`, на первом экране нет картинки, а текст занимает всю ширину.

## Как добавить язык

Все тексты лежат в папке `langs/`, по файлу на язык. Имя файла задаёт код языка: `ru.yaml`, `kz.yaml`, `mn.yaml`, `uz.yaml`, `en.yaml`.

1.  Скопировать `langs/ru.yaml` в `langs/<код>.yaml` (например `langs/tr.yaml`) и перевести все тексты. Ключи (слева от двоеточия) не менять.
    -   Многострочные тексты пишутся после `|-` с отступом; пустая строка внутри — это новый абзац.
    -   `form.points` — подпись к числу баллов, `{n}` заменяется на число. Можно указать одну форму (`- '{n} ball'`) или 4, как в `ru.yaml`: для 0, для 1/21/31…, для 2–4/22–24…, для остальных.
    -   Строки, начинающиеся с `{`, взять в кавычки: `'{n} балл'`.
2.  При необходимости положить баннер первого экрана в `assets/` (например `form-tr.jpg`) и указать его в `data-form-image`.
3.  Сделать push — сборка в GitHub Actions соберёт релиз с новым языком.

Язык выбирается так: атрибут `data-lang="<код>"` у кнопки → `window.amw.languageCode` → `<html lang>` → первая часть адреса (`/tr/...`) → `ru`.

При сборке все файлы сверяются с `ru.yaml`: если в переводе не хватает ключей, вопросов не 10 или вариантов ответа не 3, сборка падает с ошибкой и списком того, что исправить.

## Сборка

Нужен Node.js 18+.

```bash
npm install     # один раз
npm run build   # langs/*.yaml + app.js → app.min.js, style.css → style.min.css
npm run dev     # то же без минификации + пересборка при изменении app.js, style.css, langs/*.yaml
```

`index.html` подключает собранные `app.min.js` и `style.min.css`, поэтому для локальной проверки сначала запустите `npm run build` (или держите запущенным `npm run dev`).

В GitHub Actions (`.github/workflows/build.yml`) на каждый push выполняется `npm ci && npm run build`, после чего собирается zip-архив и публикуется релиз.
